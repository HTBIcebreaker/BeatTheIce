# BeatTheIce 기획 개요

## 1. 한 줄 소개

**BeatTheIce는 파티에서 처음 만난 사람들이 자연스럽게 대화하고 함께 행동하도록 퀘스트와 보상을 제공해, 누구도 소외되지 않는 활기찬 분위기를 만드는 모바일 기반 파티 아이스브레이킹 앱이다.**

## 2. 해결하려는 문제

- 처음 만난 사람끼리는 대화를 시작할 계기와 공통 주제가 부족하다.
- 친한 사람들끼리만 모이면서 일부 참가자가 파티에서 소외될 수 있다.
- 호스트가 모든 참가자의 분위기와 참여 상태를 직접 챙기기 어렵다.
- 단순한 자기소개만으로는 참가자 간 상호작용이 지속되기 어렵다.

## 3. 제품 목표

1. 참가자에게 부담이 적고 명확한 행동 계기를 제공한다.
2. QR 프로필 교환과 퀘스트를 통해 새로운 사람과의 만남을 촉진한다.
3. 호스트가 공지, 미션, 결과 발표로 파티의 흐름을 주도할 수 있게 한다.
4. 보상과 롤링 페이퍼를 통해 참여 동기와 긍정적인 기억을 남긴다.

## 4. 대상 사용자와 역할

### PARTY HOST

파티를 개설하고 전체 진행을 관리하는 사용자다.

- 파티 등록 및 기본 정보 설정
- 게스트 초대 또는 참가 승인
- 일반 메시지, 미션, 미션 결과 발표
- 퀘스트와 완료 조건 등록
- 보상 설정 및 지급
- 참가 현황과 미션 진행 상태 확인

### PARTY GUEST

파티에 참가해 다른 사람과 교류하고 퀘스트를 수행하는 사용자다.

- 파티 참가 및 프로필 등록
- 자신의 QR 표시
- 상대방 QR 스캔 및 프로필 확인
- 미션 확인, 수행 결과 제출
- 보상 확인 및 수령
- 롤링 페이퍼 작성 및 확인

## 5. 핵심 사용자 흐름

게스트 경험은 하나의 순차적인 여정이 아니라, 파티가 진행되는 동안 반복되는 두 개의 핵심 플로우로 구성된다.

### 플로우 A: P2P 만남과 프로필 교환

두 참가자가 현장에서 직접 만나 서로의 QR을 인식하고 프로필을 교환한다. 공개된 프로필 정보를 대화 소재로 활용해 자연스럽게 이야기를 이어간다.

`두 사람이 만남 → 서로 QR 인식 → 상대 프로필 확인 → 프로필을 소재로 대화`

- 교환 주체는 게스트와 게스트다.
- QR 인식은 대면 만남과 대화를 시작하기 위한 장치다.
- 미션이 없어도 이 플로우는 독립적으로 반복할 수 있다.

### 플로우 B: 실시간 미션 수행

호스트가 파티 전체 또는 대상 게스트에게 미션을 띄우면 참가자가 이를 확인하고 수행한 뒤 결과를 제출한다.

`호스트가 미션 발행 → 게스트가 미션 확인 → 미션 수행 → 결과 제출 → 결과 발표 및 보상`

- 미션은 P2P 교류 도중 언제든 시작될 수 있다.
- 미션 수행 후 참가자는 다시 P2P 만남과 대화로 돌아간다.
- 미션 내용에 따라 특정 상대와의 교류를 유도할 수 있다.

### 호스트 운영 흐름

`호스트 등록 → 파티 생성 → 게스트 초대 → 파티 진행 관찰 → 필요 시 공지/미션 발행 → 결과 발표 및 보상 → 파티 종료`

## 6. 핵심 기능

### 파티 및 사용자

- 파티 등록: 파티명, 소개, 일시, 장소, 참여 코드 또는 초대 링크
- 호스트 등록: 호스트 계정과 파티 관리 권한 설정
- 게스트 등록: 이름, 프로필 사진, MBTI, 한 줄 소개
- 참가자 QR: 본인 프로필 공유 및 상대방 프로필 열람

### 메시지와 진행

- 호스트 메시지를 메인 화면 팝업 또는 배너로 실시간 노출
- 메시지 유형
  - 일반: 공지, 안내, 분위기 전환 멘트
  - 미션: 수행할 퀘스트와 조건 안내
  - 미션 결과: 성공 여부, 당첨자, 순위 또는 결과 발표

### 미션과 보상

- 호스트의 미션 제목, 설명, 제한 시간, 완료 조건 등록
- 게스트의 텍스트 또는 이미지 기반 수행 결과 제출
- 호스트의 제출 결과 확인 및 승인
- 승인된 참가자에게 보상 지급 및 수령 상태 표시

### 롤링 페이퍼

- 파티 참가자에게 메시지 작성
- 작성자 공개 또는 익명 여부 설정
- 파티 종료 후 받은 메시지 모아보기

## 7. 화면 구성

### MAIN

파티 진행 중 가장 자주 사용하는 홈 화면이다.

- 호스트 메시지 영역
  - 일반, 미션, 미션 결과 유형을 시각적으로 구분
  - 최신 메시지와 현재 진행 중인 미션 우선 표시
- 내 프로필 카드
  - QR 코드
  - 프로필 사진
  - 이름
  - MBTI
  - 한 줄 소개
- 상대방 영역
  - QR 스캔 진입 버튼
  - 스캔 완료 후 상대방 프로필 사진, 이름, MBTI, 한 줄 소개 표시
  - 대화 또는 미션으로 이어지는 행동 버튼

### SUB: 미션 제출

- 미션 제목과 설명
- 완료 조건과 제한 시간
- 텍스트 입력 또는 이미지 첨부
- 제출 상태: 미제출, 제출 완료, 승인, 반려
- 결과 및 보상 확인

### 추가 필요 화면

- 온보딩 및 역할 선택
- 파티 생성/참가
- 프로필 등록/수정
- 호스트 관리 화면
- 미션 생성/관리
- 보상 관리
- 롤링 페이퍼 작성/열람

## 8. MVP 범위

### 포함

- 호스트/게스트 역할 구분
- 파티 생성 및 참여 코드로 입장
- 참가자 프로필과 QR 표시/스캔
- 실시간 호스트 메시지 3종
- 미션 생성, 조회, 제출, 승인
- 보상 내용 및 수령 상태 표시
- 롤링 페이퍼 작성과 파티 종료 후 열람

### 후순위

- 소셜 로그인과 외부 메신저 초대
- 미션 추천 및 자동 생성
- 참가자 매칭 추천
- 랭킹, 포인트, 배지 등 고도화된 게임화
- 유료 보상 결제 및 쿠폰 시스템 연동
- 파티 통계와 운영 분석

## 9. 제품 원칙

- **소외 방지:** 특정 인기 참가자에게만 상호작용이 집중되지 않도록 설계한다.
- **낮은 진입 장벽:** 별도 설명 없이도 파티 현장에서 바로 사용할 수 있어야 한다.
- **행동 중심:** 정보 열람보다 대화, 스캔, 미션 수행 등 다음 행동을 명확히 제시한다.
- **호스트 주도, 게스트 간편:** 진행 권한은 호스트에게 주고 게스트 조작은 최소화한다.
- **현장 가독성:** 어두운 공간, 이동 중 사용, 짧은 집중 시간을 고려한 모바일 UI를 사용한다.
- **안전과 동의:** 프로필 공개 범위, 사진 촬영, 익명 메시지에 대한 동의와 신고 수단을 고려한다.

## 10. 성공 지표 초안

- 초대된 게스트 대비 파티 참가 완료율
- 참가자 1인당 QR 스캔 또는 새 프로필 확인 수
- 미션 조회 대비 제출률 및 승인률
- 참가자 1인당 서로 다른 교류 상대 수
- 롤링 페이퍼 작성 참여율
- 파티 종료 후 만족도와 재사용 의향

## 11. 미결정 사항

- 로그인 없이 닉네임 기반으로 사용할지, 계정 가입을 필수로 할지
- QR 스캔 후 프로필을 저장할지, 파티 중에만 임시 공개할지
- 미션 제출 증빙 형식과 호스트 승인 방식
- 보상이 앱 내부 포인트인지, 현장 실물 보상 안내인지
- 롤링 페이퍼 공개 시점과 익명 허용 범위
- 한 사용자가 여러 파티에서 호스트와 게스트 역할을 전환할 수 있는 방식
- 부적절한 프로필, 사진, 메시지에 대한 신고 및 운영 정책

## 12. 90분 프로토타입 개발 기준

### 개발 조건

- 개발 인원: 4명
- 개발 시간: 90분
- 프로젝트 구조: 하나의 Next.js App Router 프로젝트
- 작업 방식: 프론트엔드와 백엔드를 별도 프로젝트로 분리하지 않고 기능 단위로 병렬 개발
- 목표: 운영 가능한 정식 서비스가 아니라 핵심 가치가 전달되는 모바일 데모 완성
- 서버·데이터베이스: 사용하지 않음
- 데모 상태: 코드에 포함된 mock 데이터와 브라우저 상태로 관리

### 반드시 시연할 두 플로우

1. **P2P 프로필 교환:** 두 게스트가 QR을 통해 상대방 프로필을 확인하고 대화를 시작한다.
2. **실시간 미션:** 호스트가 미션을 띄우고 게스트가 확인·제출한 뒤 결과와 보상을 확인한다.

### 90분 범위

- 모바일 MAIN 화면
- 고정된 데모 파티 입장
- 게스트 프로필 표시와 QR 생성
- QR 스캔 성공을 재현하는 데모 동작
- 호스트의 일반·미션·결과 메시지 전환
- 게스트의 텍스트 미션 제출
- 보상 결과 표시
- 간단한 롤링 페이퍼 작성·표시

### 제외 또는 대체

- 실제 회원가입·로그인 → 데모 사용자 선택으로 대체
- 완전한 파티 CRUD → 하나의 고정 데모 파티로 대체
- 실제 카메라·다기기 QR 검증 실패 시 → 스캔 성공 버튼 또는 샘플 QR로 대체
- 이미지 업로드 → 텍스트 제출만 지원
- 실제 쿠폰 지급 → 보상 문구 표시로 대체
- 복잡한 DB·권한 정책 → mock 데이터와 `localStorage` 사용
- 모든 예외 처리와 운영자 기능 → 발표 시나리오에 필요한 범위만 구현

### 성공 기준

- 모바일 화면에서 두 핵심 플로우를 중단 없이 시연할 수 있다.
- HOST와 GUEST 역할의 차이가 화면에서 명확히 보인다.
- 일반, 미션, 미션 결과 메시지가 시각적으로 구분된다.
- 새로고침이나 재실행 전에 발표용 상태가 깨지지 않는다.
- 하나의 Next.js 프로젝트만 설치하고 실행하면 전체 데모를 확인할 수 있다.

## 13. 문서 운영 원칙

- 이 문서는 제품 방향과 범위의 최상위 기준(Single Source of Truth)이다.
- 세부 화면, 정책, 데이터 모델은 후속 문서로 분리하되 이 문서와 충돌하지 않아야 한다.
- 범위나 핵심 정책이 변경되면 구현보다 먼저 이 문서를 갱신한다.
