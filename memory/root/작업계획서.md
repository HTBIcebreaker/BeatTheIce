# 작업계획서

## 작업자

`root`

## 목표

BeatTheIce 저장소에 memory 기반 SOT 운영 구조를 준비하고, 향후 모든 작업이 해당 문서와 runbook에 근거하도록 한다.

## 계획

1. 저장소의 `runbook.md`, `AGENTS.md`, `memory` 존재 여부를 확인한다.
2. `memory` 최상위에 공통 기획 개요를 작성한다.
3. `memory/root`에 작업계획서와 작업 내역서를 작성한다.
4. `runbook.md`가 공유되면 전문을 읽고 팀 스킬 및 운영 규칙을 관련 문서에 반영한다.
5. 각 작업 완료 후 결과와 memory SOT 간 위배 여부를 점검하고 작업 내역서에 기록한다.

## 완료 기준

- 필수 memory 문서 3종이 존재한다.
- 향후 작업에 적용할 SOT 우선순위와 완료 후 검증 절차가 문서화되어 있다.
- runbook 부재 상태와 후속 조치가 기록되어 있다.

## 2026-08-29 — Next.js 전환 작업계획

### 목표

기존 Vite + React + Express/Socket.IO 기반 party-icebreaker 앱의 기능을 그대로 유지하면서, 프로젝트를 Next.js(App Router) 기반으로 전환한다.

### 계획

1. 작업 전 `memory/기획 개요.md`를 재확인하고 SOT 원칙을 준수한다.
2. 기존 소스(`src/App.jsx`, `src/main.jsx`, `src/components`, `src/views`, `src/context`, `server/index.js`, `server/store.js`)를 전부 읽고 기능/데이터 흐름을 파악한다.
3. UI는 URL 라우팅이 아닌 tab 상태 기반 SPA 구조이므로, 리스크 최소화를 위해 `next/dynamic`(`ssr:false`)으로 클라이언트 전용 렌더링을 적용해 SSR 관련 브라우저 API 이슈를 원천 차단한다.
4. Socket.IO 실시간 기능은 Next 표준 API Route로 대체할 수 없으므로, Next 요청 핸들러 + Express REST API + Socket.IO를 한 프로세스에서 구동하는 커스텀 서버(`server.js`)로 통합한다.
5. REST API 로직(`server/index.js`)은 문구/동작 변경 없이 `server/api.js`(Express Router 팩토리)로 이전한다.
6. `package.json`, `tailwind.config.js`, `.gitignore`, `README.md`를 Next 기준으로 갱신한다.
7. 빌드(`next build`) 및 프로덕션 서버 기동 후 브라우저로 실제 화면·API·Socket.IO·미션완료 리워드 플로우를 검증한다.
8. 작업 완료 후 결과가 memory SOT와 충돌하지 않는지 점검하고 작업 내역서에 기록한다.

### 완료 기준

- 기존 화면(홈/퀘스트/스캔/롤링페이퍼/MY)과 모달, 실시간 브로드캐스트, 리워드 지급 로직이 동일하게 동작한다.
- `npm run build`가 에러 없이 성공한다.
- 실제 브라우저 테스트로 REST API 호출과 Socket.IO 이벤트가 정상 동작함을 확인한다.
