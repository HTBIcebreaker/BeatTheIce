## 2. 수행 내역

### 기능 구조

- `src/features/rolling-paper` 독립 기능 디렉터리를 추가했다.
- 기존 `src/views/RollingPaperView.jsx`는 Context의 파티·프로필을 독립 기능에 연결하는 얇은 bridge로 정리했다.
- 공통 App, Header, BottomNav, 다른 담당자의 feature 파일은 수정하지 않았다.

### 롤링 페이퍼 UI

- 같은 파티의 개인 수신자만 선택하도록 구현했다. SQL의 `receiver_id` FK와 맞지 않는 기존 `파티원 전체` 선택은 제거했다.
- 1~500자 메시지, 자기 자신 수신 금지, 수신자 필수 검증을 추가했다.
- 익명 선택, 저장 중·성공·실패 피드백, 빈 수신함을 구현했다.
- 파티가 `ENDED`가 아니면 받은 메시지를 잠그고 공개 예정 안내를 표시한다.
- 수신함은 현재 사용자에게 온 메시지만 표시하며, 익명 메시지는 발신자 ID·이름을 UI에 노출하지 않는다.

### adapter·폴백

- Supabase 환경변수와 UUID 파티·프로필이 있으면 `rolling_messages` insert와 `list_received_rolling_messages` RPC를 사용한다.
- 인증·환경변수가 없는 현재 배포 환경은 `localStorage` adapter로 자동 전환해 작성·익명·새로고침 보존을 시연할 수 있다.
- Socket/REST에서 늦게 들어온 seed 메시지를 ID로 병합해 localStorage 메시지와 중복되지 않게 했다.
- adapter 단계에서 SQL snake_case와 UI camelCase를 정규화한다.

### SQL·보안

- 후속 마이그레이션 `20260829074000_rolling_paper_security.sql`을 추가했다. 원격에서 이동된 초기 스키마는 수정하지 않았다.
- `rolling_messages` 원본 select는 발신자 본인에게만 허용하도록 RLS를 변경했다.
- `list_received_rolling_messages(target_party_id)` security-definer RPC를 추가했다.
- RPC는 현재 사용자가 수신자이고 파티가 `ENDED`인 메시지만 반환한다.
- 익명 메시지는 RPC에서 `sender_id = null`, `sender_name = '익명의 파티원'`으로 마스킹한다.
- `rolling_messages`를 Supabase Realtime publication 대상에 추가했다.

### 모바일 브라우저 검증

- 하단 `롤링페이퍼` 탭 진입 성공.

- 가로 스크롤 없음, 브라우저 console error 0건.

## 5. 운영·배포 유의사항

- 실제 Supabase 동작을 위해 `supabase/migrations/20260829074000_rolling_paper_security.sql` 마이그레이션을 적용해야 한다.
- Vercel에 `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`를 설정해야 한다.
- 현재 앱의 mock `guest_001` 형식이 아닌 Supabase Auth UUID 프로필·파티가 연결되면 Supabase adapter가 활성화된다.
- Supabase JS 2.112.4의 engine 조건에 맞춰 배포·CI는 Node 22 이상을 사용해야 한다.
- `npm audit --omit=dev`에서 기존 Next.js 14·PostCSS 계열 high 2건이 확인됐다. 자동 수정은 Next.js 16 강제 업그레이드를 요구하므로 4인분 기능 범위에서 적용하지 않고 후속 통합 이슈로 남겼다.
