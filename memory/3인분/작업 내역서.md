# 3인분 작업 내역서

## 담당

`3인분 — 호스트 메시지·미션·결과·보상`

## 2026-08-29 수행 내역

### 미션 모델과 서버 흐름

- 미션에 `submissionType(TEXT/PHOTO)`과 `status`를 추가했다.
- `missionSubmissions` 저장소와 제출 조회 API를 추가했다.
- 미션 제출 API에서 미션·게스트 존재, 활성 상태, 제출 형식과 중복 제출을 검증한다.
- HOST 판정 API에서 `APPROVED`와 `REJECTED` 상태 전이를 검증한다.
- 승인 시에만 게스트 포인트, 완료 미션과 보상 쿠폰을 한 번 발급한다.
- 승인 결과 팝업과 제출·판정 Socket.IO 이벤트를 추가했다.
- 사진 Data URL을 받을 수 있도록 JSON 요청 제한을 3MB로 설정했다.

### GUEST 미션 제출 UI

- 미션 카드에 텍스트 인증과 사진 인증 유형을 표시한다.
- 텍스트 미션 입력과 제출 기능을 구현했다.
- 모바일 카메라 또는 앨범에서 사진을 선택할 수 있게 했다.
- Canvas에서 사진을 최대 1280px, JPEG 품질 0.72로 압축한다.
- 사진 미리보기, 다시 촬영, 제출 진행과 오류 상태를 구현했다.
- 제출 대기, 승인·보상 완료, 반려 사유와 재제출 상태를 구현했다.

### HOST 미션 운영 UI

- 미션 생성 화면에 TEXT/PHOTO 제출 방식 선택을 추가했다.
- HOST 컨트롤 센터에 `제출 검수` 탭을 추가했다.
- 제출자의 텍스트와 인증 사진, 현재 판정 상태를 표시한다.
- 승인·보상과 반려 동작을 연결했다.

### 알파 연결 지점

- 현재 REST/Socket 기반 mission adapter는 독립적으로 동작한다.
- Supabase `missions`, `mission_submissions` 연결은 공유 데이터 계층과 겹치므로 `ALPHA-TODO(owner: mission, consumer: shared-data)`로 기록했다.
- 알파 사이클에서 동일한 Context 함수 계약을 유지한 채 Supabase adapter로 교체할 수 있다.
