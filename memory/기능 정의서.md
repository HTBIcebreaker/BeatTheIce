# BeatTheIce 기능 정의서

## 1. 문서 목적

이 문서는 BeatTheIce MVP에서 제공할 기능의 동작, 사용자 권한, 상태, 예외 조건과 완료 기준을 정의한다. 제품 방향과 범위는 `memory/기획 개요.md`를 최상위 기준으로 삼는다.

## 2. 서비스 구조

BeatTheIce의 게스트 경험은 하나의 순차 흐름이 아니라 다음 두 플로우가 파티 진행 중 독립적으로 반복되는 구조다.

### 플로우 A: P2P 프로필 교환과 대화

`두 게스트가 만남 → 서로 QR 인식 → 상대 프로필 확인 → 프로필을 소재로 대화`

### 플로우 B: 실시간 미션 수행

`호스트가 미션 발행 → 게스트가 미션 확인 → 수행 결과 제출 → 호스트가 결과 확정 → 결과 발표 및 보상`

미션은 P2P 대화 중 언제든 시작될 수 있으며, 미션이 종료되면 게스트는 다시 P2P 교류를 이어간다.

## 4. 공통 상태 정의

### 파티 상태

| 상태 | 설명 |
| --- | --- |
| `READY` | 파티가 생성됐지만 아직 시작되지 않음 |
| `ACTIVE` | 게스트 입장과 실시간 진행이 가능한 상태 |
| `ENDED` | 파티가 종료되어 신규 상호작용이 제한된 상태 |

### 미션 상태

| 상태 | 설명 |
| --- | --- |
| `DRAFT` | 호스트가 작성 중인 미션 |
| `ACTIVE` | 게스트에게 발행되어 수행 가능한 미션 |
| `JUDGING` | 제출이 마감되고 호스트가 결과를 확인하는 상태 |
| `ANNOUNCED` | 결과와 보상이 발표된 상태 |
| `CANCELLED` | 호스트가 취소한 미션 |

### 제출 상태

| 상태 | 설명 |
| --- | --- |
| `NOT_SUBMITTED` | 아직 제출하지 않음 |
| `SUBMITTED` | 제출 완료, 판정 대기 중 |
| `APPROVED` | 성공으로 승인됨 |
| `REJECTED` | 조건 미충족으로 반려됨 |

## 6. 상세 기능 정의

### AUTH-01 역할 선택 및 사용자 등록

- 목적: 사용자가 파티에서 수행할 역할과 기본 식별 정보를 설정한다.
- 선행 조건: 앱에 처음 진입했거나 사용자 정보가 없는 상태다.
- 입력
  - 역할: `HOST` 또는 `GUEST`
  - 이름 또는 닉네임
  - 프로필 사진
  - MBTI
  - 한 줄 소개
- 처리
  1. 필수 항목을 검증한다.
  2. 사용자와 역할 정보를 저장한다.
  3. HOST는 파티 생성, GUEST는 파티 참가 화면으로 이동한다.
- 출력: 등록된 사용자 프로필과 역할별 시작 화면
- 예외
  - 필수 이름이 없으면 등록할 수 없다.
  - 이미지 업로드 실패 시 재시도하거나 기본 이미지를 사용할 수 있다.
- 완료 기준
  - 등록 후 앱을 다시 열어도 동일한 사용자 정보가 유지된다.
  - 역할에 맞는 기능만 노출된다.

### PARTY-01 파티 생성

- 목적: HOST가 게스트가 참가할 파티 공간을 만든다.
- 사용자: HOST
- 선행 조건: 호스트 등록이 완료되어 있다.
- 입력
  - 파티명
  - 파티 소개
  - 일시
  - 장소
- 처리
  1. 파티 정보를 저장한다.
  2. 중복되지 않는 참여 코드를 생성한다.
  3. 파티 상태를 `READY`로 설정한다.
- 출력: 파티 정보, 참여 코드, 공유 가능한 참가 안내
- 예외: 필수 파티명이 없거나 일시 형식이 잘못되면 생성할 수 없다.
- 완료 기준: 생성한 파티가 호스트 관리 화면에 표시되고 참여 코드로 조회된다.

### PARTY-02 참여 코드로 파티 참가

- 목적: GUEST가 특정 파티에 입장한다.
- 사용자: GUEST
- 선행 조건: 게스트 프로필이 등록되어 있다.
- 입력: 참여 코드
- 처리
  1. 참여 코드와 파티 상태를 확인한다.
  2. 게스트를 파티 참가자 목록에 등록한다.
  3. 파티 MAIN 화면으로 이동한다.
- 출력: 파티명, 호스트 안내, 참가자용 MAIN 화면
- 예외
  - 존재하지 않는 코드면 오류를 표시한다.
  - 종료된 파티면 신규 참가를 막는다.
  - 이미 참가한 사용자면 중복 등록 없이 기존 파티로 이동한다.
- 완료 기준: 참가 직후 본인 프로필과 현재 호스트 메시지를 확인할 수 있다.

### PARTY-03 파티 진행 및 종료

- 목적: HOST가 파티의 시작과 종료 상태를 관리한다.
- 사용자: HOST
- 처리
  - 시작 시 상태를 `ACTIVE`로 변경한다.
  - 종료 시 상태를 `ENDED`로 변경하고 활성 미션을 마감한다.
- 출력: 모든 참가자 화면에 변경된 파티 상태 표시
- 예외: 파티 종료 전 확인 절차를 제공한다.
- 완료 기준: 종료 후 신규 참가와 신규 미션 제출이 차단된다.

### PROF-01 내 프로필 등록·수정

- 목적: P2P 만남에서 대화 소재가 될 정보를 구성한다.
- 사용자: HOST, GUEST
- 입력
  - 프로필 사진
  - 이름
  - MBTI
  - 한 줄 소개
- 처리: 입력값을 검증하고 사용자의 최신 프로필로 저장한다.
- 출력: MAIN의 내 프로필 카드와 QR에 반영된 최신 정보
- 예외: 이름은 비워둘 수 없고 한 줄 소개는 정해진 글자 수를 넘길 수 없다.
- 완료 기준: 수정 후 상대방이 QR을 스캔하면 최신 프로필이 표시된다.

### PROF-02 내 QR 표시

- 목적: 대면한 상대가 내 프로필을 빠르게 열 수 있게 한다.
- 사용자: HOST, GUEST
- 입력: QR 보기 선택
- 처리: 사용자와 현재 파티를 식별할 수 있는 만료 가능한 값을 QR로 표현한다.
- 출력: 밝기와 크기를 확보한 전체 또는 확대 QR 화면
- 예외: 오프라인이거나 QR 생성 실패 시 재시도 안내를 표시한다.
- 완료 기준: 같은 파티 참가자가 QR을 인식해 내 공개 프로필을 열 수 있다.

### PROF-03 상대 QR 스캔 및 프로필 확인

- 목적: 두 사람이 프로필을 교환하고 대화를 시작하게 한다.
- 사용자: HOST, GUEST
- 선행 조건: 카메라 권한이 있고 `ACTIVE` 파티에 참가 중이다.
- 입력: 상대방 QR
- 처리
  1. 카메라 권한을 확인한다.
  2. QR의 유효성과 현재 파티 참가자인지 확인한다.
  3. 상대방 공개 프로필을 불러온다.
  4. MAIN의 상대방 영역에 프로필을 표시한다.
- 출력: 상대방 사진, 이름, MBTI, 한 줄 소개
- 예외
  - 카메라 권한이 없으면 설정 이동 안내를 표시한다.
  - 다른 파티, 만료, 손상된 QR은 인식하지 않는다.
  - 자기 QR을 스캔하면 안내 후 처리를 중단한다.
- 완료 기준
  - 스캔 성공 후 1회 조작 이내에 상대 프로필이 표시된다.
  - 미션 없이도 다른 상대와 계속 반복할 수 있다.

### MSG-01 일반 공지 발행·수신

- 목적: HOST가 파티 참가자에게 실시간 안내를 전달한다.
- 사용자: 발행 HOST, 수신 GUEST
- 입력: 일반 메시지 본문
- 처리: 현재 파티 참가자에게 메시지를 실시간 전송하고 최신 메시지로 저장한다.
- 출력: MAIN 상단 팝업 또는 배너
- 예외: 빈 메시지는 발행할 수 없다.
- 완료 기준: 접속 중인 게스트 화면에 메시지 유형과 내용이 즉시 구분되어 표시된다.

### MISS-01 미션 생성 및 발행

- 목적: HOST가 파티 중 참가자의 행동을 유도한다.
- 사용자: HOST
- 입력
  - 미션 제목
  - 설명
  - 완료 조건
  - 제한 시간 또는 마감 시각
  - 제출 형식: 텍스트, 이미지 또는 둘 다
  - 보상 내용
- 처리
  1. 임시 저장 시 `DRAFT`로 저장한다.
  2. 발행 시 `ACTIVE`로 변경한다.
  3. 대상 게스트의 MAIN에 미션 팝업을 실시간 노출한다.
- 출력: 발행된 미션과 마감 정보
- 예외: 제목, 완료 조건 또는 마감 정보가 유효하지 않으면 발행할 수 없다.
- 완료 기준: 발행 즉시 게스트가 미션 상세와 제출 화면에 접근할 수 있다.

### MISS-02 미션 확인 및 수행 결과 제출

- 목적: GUEST가 발행된 미션을 수행하고 결과를 제출한다.
- 사용자: GUEST
- 선행 조건: 미션 상태가 `ACTIVE`이고 마감 전이다.
- 입력: 미션에서 허용한 텍스트 및 이미지
- 처리
  1. 제출 형식과 필수 값을 검증한다.
  2. 결과를 저장하고 상태를 `SUBMITTED`로 변경한다.
  3. 호스트에게 신규 제출을 표시한다.
- 출력: 제출 완료 시각과 판정 대기 상태
- 예외
  - 마감되거나 취소된 미션은 제출할 수 없다.
  - 이미지 업로드 실패 시 제출 완료로 처리하지 않는다.
  - MVP에서는 제출 후 수정 가능 여부를 미션 마감 전으로 제한한다.
- 완료 기준: 제출 내용이 호스트 관리 화면에 누락 없이 표시된다.

### MISS-03 제출 확인 및 결과 판정

- 목적: HOST가 게스트의 미션 수행 결과를 확인한다.
- 사용자: HOST
- 입력: 제출별 승인 또는 반려, 선택적 판정 메모
- 처리: 제출 상태를 `APPROVED` 또는 `REJECTED`로 변경한다.
- 출력: 참가자별 제출 및 판정 상태
- 예외: 이미 결과 발표가 끝난 미션의 판정은 변경할 수 없다.
- 완료 기준: 모든 제출의 현재 판정 상태를 호스트가 한 화면에서 확인할 수 있다.

### MISS-04 미션 결과 발표

- 목적: 참가자에게 미션 결과를 실시간으로 알린다.
- 사용자: 발행 HOST, 수신 GUEST
- 선행 조건: 미션 상태가 `JUDGING`이며 필요한 판정이 완료되어 있다.
- 입력: 발표 문구, 성공자 또는 수상자, 보상 정보
- 처리
  1. 결과를 확정한다.
  2. 미션 상태를 `ANNOUNCED`로 변경한다.
  3. 결과 발표 팝업을 참가자에게 전송한다.
- 출력: MAIN의 미션 결과 발표와 개인별 결과
- 예외: 결과 대상이나 발표 문구가 없으면 발표 전 확인을 요구한다.
- 완료 기준: 게스트가 일반 공지 및 신규 미션과 다른 형태로 결과 발표를 인식할 수 있다.

### REWD-01 보상 설정·지급·확인

- 목적: 미션 참여 동기를 제공하고 성공자에게 보상 내용을 전달한다.
- 사용자: 설정·지급 HOST, 확인 GUEST
- MVP 보상 형태: 앱 외부에서 제공하는 실물 보상 또는 쿠폰에 대한 텍스트 안내
- 입력: 보상명, 설명, 지급 대상
- 처리: 결과 발표 시 승인된 대상에게 보상을 배정하고 지급 상태를 기록한다.
- 출력: 게스트의 보상명, 설명, 지급 상태
- 예외: 발표되지 않은 미션의 보상은 지급 완료로 처리할 수 없다.
- 완료 기준: 호스트와 대상 게스트가 동일한 보상 지급 상태를 확인할 수 있다.

### ROLL-01 롤링 페이퍼 메시지 작성

- 목적: 참가자가 파티에서 만난 사람에게 긍정적인 메시지를 남긴다.
- 사용자: HOST, GUEST
- 선행 조건: 같은 파티 참가자다.
- 입력: 수신자, 메시지 본문, 작성자 공개 여부
- 처리: 메시지를 저장하고 파티 공개 정책에 따라 열람 전까지 숨긴다.
- 출력: 작성 완료 상태
- 예외
  - 본문이 없거나 글자 수 제한을 초과하면 저장할 수 없다.
  - 자기 자신에게는 작성할 수 없다.
- 완료 기준: 작성자는 중복 제출 여부를 확인할 수 있고 수신자는 정해진 시점에 메시지를 받는다.

### ROLL-02 받은 롤링 페이퍼 열람

- 목적: 파티가 끝난 뒤 참가자가 받은 메시지를 모아본다.
- 사용자: HOST, GUEST
- 선행 조건: 파티 상태가 `ENDED`다.
- 처리: 현재 사용자가 받은 메시지만 조회한다.
- 출력: 받은 메시지 목록과 공개로 설정된 작성자 정보
- 예외: 파티 종료 전에는 공개 예정 안내만 표시한다.
- 완료 기준: 익명 메시지에는 작성자 식별 정보가 노출되지 않는다.

## 7. MAIN 화면 기능 정의

### 우선순위

MAIN은 현재 파티 상황과 다음 행동을 한눈에 보여준다. 화면의 정보 우선순위는 다음과 같다.

1. 새 미션 또는 미션 결과 팝업
2. 최신 호스트 일반 공지
3. 내 프로필과 QR
4. QR 스캔 및 상대방 프로필

### 메시지 팝업 유형

| 유형 | 목적 | 주요 행동 |
| --- | --- | --- |
| 일반 | 호스트 안내 전달 | 확인 또는 닫기 |
| 미션 | 새로운 미션 시작 알림 | 미션 보기 |
| 미션 결과 | 성공자와 보상 발표 | 결과·보상 확인 |

### 내 프로필 영역

- 프로필 사진, 이름, MBTI, 한 줄 소개를 표시한다.
- QR을 즉시 확대할 수 있어야 한다.
- 프로필 수정 화면으로 이동할 수 있어야 한다.

### 상대방 영역

- 스캔 전에는 QR 스캔 행동을 가장 크게 제시한다.
- 스캔 후에는 상대방 사진, 이름, MBTI, 한 줄 소개를 표시한다.
- 다른 사람 스캔을 선택하면 기존 상대 정보가 새 상대 정보로 교체된다.

## 8. SUB 미션 제출 화면 기능 정의

- 미션 제목, 설명, 완료 조건을 표시한다.
- 남은 시간 또는 마감 시각을 표시한다.
- 미션이 요구하는 텍스트 입력과 이미지 첨부만 활성화한다.
- 제출 전 입력 내용을 확인할 수 있어야 한다.
- 제출 후 `제출 완료`, `승인`, `반려` 상태를 표시한다.
- 결과 발표 후 결과와 보상 정보를 표시한다.
- 미션 도중 화면을 나가도 작성 중인 내용을 임시 보존하는 것을 권장한다.

## 9. 실시간 동기화 대상

다음 이벤트는 같은 파티의 관련 사용자 화면에 실시간 반영되어야 한다.

- 파티 시작 및 종료
- 호스트 일반 공지
- 미션 발행, 마감, 취소
- 신규 미션 제출
- 제출 승인 및 반려
- 미션 결과 발표
- 보상 지급 상태 변경

연결이 일시적으로 끊긴 사용자는 재접속 시 서버의 최신 상태를 다시 받아 화면을 복구한다.

## 10. 공통 예외 및 정책

- 모든 변경 기능은 현재 사용자 역할과 파티 소속을 서버에서 다시 검증한다.
- 프로필은 같은 파티 참가자에게만 공개한다.
- QR에는 이름이나 소개문 같은 개인정보를 직접 넣지 않고 조회용 식별 값만 포함한다.
- 중복 요청으로 파티 참가, 미션 제출, 결과 발표가 두 번 생성되지 않게 처리한다.
- 카메라와 이미지 접근 전 사용자 권한을 요청하고 거절 시 대체 안내를 제공한다.
- 부적절한 프로필과 롤링 페이퍼에 대응할 신고·차단 정책은 MVP 상세 정책에서 확정한다.

## 11. MVP 제외 범위

- 앱 내부 결제와 실제 쿠폰 자동 발급
- AI 미션 자동 생성
- 참가자 자동 매칭 추천
- 포인트, 레벨, 배지, 리더보드
- 파티 운영 통계 대시보드
- 파티 종료 후 참가자 간 상시 채팅

## 12. 추가 결정 필요 사항

- 가입 없이 파티별 임시 사용자로 이용할지 여부
- QR 교환 이력을 저장하고 사용자에게 보여줄지 여부
- 하나의 미션을 개인 단위로 제출할지 팀 단위 제출도 지원할지
- 미션별 대상자를 전체, 개인, 그룹 중 어디까지 지정할지
- 반려된 제출의 재제출 허용 여부
- 보상 지급 완료를 호스트만 처리할지 게스트 수령 확인도 받을지
- 롤링 페이퍼 작성 가능 시점과 익명 허용 범위
- 호스트도 일반 참가자로서 미션에 참여할 수 있는지 여부
